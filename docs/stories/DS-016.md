# Story: Add Sandbox Watch (Live Event Stream)

## Narrative
- **As a** factory operator or DarkClaw orchestration engine
- **I want to** run `darkshell sandbox watch <name>` and receive a real-time stream of sandbox events (commands executed, files changed, network requests, policy decisions) as JSON lines
- **So that** I can monitor agent behavior in real-time without SSH-ing into the sandbox, enabling live dashboards, automated alerting, and CI/CD integration

## Acceptance Criteria

### AC-001: Watch streams events in real-time as JSON lines
`darkshell sandbox watch <name>` outputs a continuous stream of newline-delimited JSON objects to stdout. Each event includes `timestamp`, `event_type`, `sandbox`, and type-specific payload fields. Events appear within 1 second of the action occurring in the sandbox (NFR-013).
- **Test:** `test_watch_streams_events_as_json_lines()`

### AC-002: Events are filterable by event type
`darkshell sandbox watch <name> --type <event_type>` filters the stream to only include events of the specified type. Supported types include: `command`, `file`, `network`, `policy`, `lifecycle`. Multiple `--type` flags can be combined.
- **Test:** `test_watch_filters_by_event_type()`

### AC-003: Watch auto-reconnects on connection drop
If the underlying connection to the gateway event source drops (network interruption, gateway restart), the watch client automatically reconnects with exponential backoff (1s, 2s, 4s, max 30s). A warning is emitted to stderr on each reconnect attempt. Events occurring during the disconnected window are not guaranteed but the stream resumes without user intervention.
- **Test:** `test_watch_auto_reconnects_on_connection_drop()`

### AC-004: Watch supports --json flag for machine-readable output
`darkshell sandbox watch <name> --json` is the default mode (JSON lines). Without `--json`, events are displayed in a human-readable format with colored output when stderr is a TTY. Both modes stream the same events.
- **Test:** `test_watch_human_readable_format()`

### AC-005: Watch exits cleanly on sandbox deletion
If the watched sandbox is deleted while `watch` is running, the stream emits a final `lifecycle:deleted` event and the process exits with code 0. No error is printed.
- **Test:** `test_watch_exits_on_sandbox_deletion()`

### AC-006: Watch reports sandbox not found with actionable error
`darkshell sandbox watch <nonexistent>` exits immediately with an error: "Sandbox 'nonexistent' not found. Available sandboxes: <list>".
- **Test:** `test_watch_reports_sandbox_not_found()`

### AC-007: Watch gracefully degrades on macOS and non-eBPF environments
On platforms where eBPF is unavailable (macOS, older Linux kernels, missing CAP_BPF), `watch` falls back to log-tailing mode. A message is emitted to stderr: "eBPF unavailable. Falling back to log-based monitoring. Some event types may be limited." The stream still delivers `network`, `policy`, and `lifecycle` events from gateway logs.
- **Test:** `test_watch_degrades_gracefully_without_ebpf()`

## Edge Cases
| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-015 | Watch connection drops (network interruption) | Auto-reconnect with exponential backoff (1s, 2s, 4s, max 30s). Warning to stderr on each attempt. Stream resumes on reconnect. |
| EC-018 | eBPF not available (macOS, older kernel, no CAP_BPF) | Graceful degradation to log-tailing-only mode. Message: "eBPF unavailable. Falling back to log-based monitoring." |
| EC-W01 | Sandbox produces events faster than the watch client can consume | Apply backpressure via bounded channel. Drop oldest events when buffer is full (1000 events). Emit a `watch:overflow` event with count of dropped events. |
| EC-W02 | User sends SIGINT (Ctrl+C) during watch | Clean shutdown: flush any buffered events, close connections, exit with code 0. No partial JSON lines emitted. |
| EC-W03 | Gateway log contains non-UTF-8 bytes | Skip the malformed line, emit a `watch:parse_error` event with the byte offset, continue processing. |
| EC-W04 | Multiple `watch` commands on the same sandbox | Each watch instance receives its own copy of the event stream. No interference between watchers. |
| EC-W05 | Watch on a sandbox that is in Provisioning phase (not yet Ready) | Stream begins immediately with `lifecycle` events. Emit `lifecycle:provisioning` events as the sandbox starts up. Transition to full event stream when sandbox reaches Ready. |

## Architecture Compliance Rules

| Rule | Source | Enforcement |
|------|--------|-------------|
| Observability is read-only — never modifies sandbox state | ADR-005, SOUL.md Rule 11 | Watch implementation only reads logs and eBPF events; no write operations to sandbox |
| eBPF probes run on host, not in sandbox | ADR-005 | eBPF probe attachment targets host kernel scoped to sandbox PID/netns |
| No modification to openshell-sandbox or openshell-server crates | ADR-001 | `git diff` of those crates must be empty |
| Graceful degradation on non-Linux platforms | NFR-016 | Runtime platform check; log-only mode on macOS/WSL with clear message |
| Actionable error messages | NFR-014, SOUL.md Rule 5 | Sandbox not found includes available sandbox list; eBPF unavailable includes fallback explanation |
| JSON output when piped (no ANSI/color in non-TTY) | NFR-017 | Check `atty::is(Stream::Stderr)` before emitting color codes |
