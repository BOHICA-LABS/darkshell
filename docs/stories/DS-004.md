# Story: Add Progress Bar to Upload and Download

## Narrative
- **As an** operator (or DarkClaw orchestration engine)
- **I want to** see a real-time progress bar showing bytes transferred, transfer rate, and ETA during upload and download operations
- **So that** I can distinguish a working large transfer from a stuck one, estimate completion time, and avoid killing transfers that are actually progressing

## Acceptance Criteria

### AC-001: Upload displays progress bar with bytes, rate, and ETA
During `darkshell sandbox upload <name> <local>`, a progress bar on stderr shows: bytes transferred / total bytes, transfer rate (MB/s), and estimated time remaining.
- **Test:** `test_upload_progress_bar_displays()`

### AC-002: Download displays progress bar with bytes and rate
During `darkshell sandbox download <name> <remote>`, a progress bar on stderr shows: bytes received and transfer rate. ETA is shown when total size can be determined.
- **Test:** `test_download_progress_bar_displays()`

### AC-003: Progress bar suppressed when stderr is not a TTY
When the CLI's stderr is piped (not a terminal), no progress bar output is emitted. No ANSI escape codes, no carriage returns, no `indicatif` output in the byte stream. This ensures programmatic use by DarkClaw is not polluted.
- **Test:** `test_progress_suppressed_when_piped()`

### AC-004: Upload total size calculated before transfer begins
Before the tar stream begins, the CLI calculates total size by summing local file sizes (respecting gitignore when applicable). This total is used for the progress bar denominator and ETA calculation.
- **Test:** `test_upload_total_size_precalculated()`

### AC-005: Download wraps tar stream in counting reader
The download tar stream is wrapped in a reader that counts bytes as they arrive, feeding the progress bar. The underlying tar extraction is unaffected.
- **Test:** `test_download_counting_reader_wraps_tar()`

### AC-006: Zero-byte upload/download completes without error
When uploading an empty directory or downloading a path with no files, the progress bar shows "0 B" and completes immediately. No division-by-zero, no infinite ETA.
- **Test:** `test_zero_byte_transfer_completes()`

### AC-007: Progress bar updates at least once per second
The progress bar refreshes at a minimum rate of 1 Hz, providing steady visual feedback even during slow transfers.
- **Test:** `test_progress_bar_update_frequency()`

## Edge Cases
| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-004 | Upload of 0-byte directory (empty or all files gitignored) | Progress bar shows "0 B / 0 B" and completes immediately with success. No division-by-zero. |
| EC-P01 | Upload of single very large file (>10GB) | Progress bar handles large byte counts correctly. Display uses human-readable units (GB). ETA updates smoothly. |
| EC-P02 | Download where total size is unknown (server doesn't report tar size) | Progress bar shows bytes received and rate without a total or ETA. Spinner mode instead of bar. |
| EC-P03 | Transfer rate drops to 0 (stalled transfer) | Progress bar shows "0 B/s" and ETA shows "--:--". No crash or panic. |
| EC-P04 | Terminal window is very narrow (< 40 columns) | `indicatif` handles narrow terminals gracefully. Template truncates rather than wrapping. |

## Architecture Compliance Rules

| Rule | Source | Enforcement |
|------|--------|-------------|
| Progress only on stderr, never stdout | NFR-017, IF-014 | `ProgressBar` draws to stderr; stdout reserved for command output |
| Suppressed when not a TTY | NFR-017 | `is_terminal()` check gates all progress output |
| No modification to tar stream content | ADR-008 | Counting reader is transparent; tar bytes pass through unmodified |
| Progress bar uses indicatif crate | Architecture COMP-006 | Not a custom progress implementation |
| Update frequency >= 1 Hz | IF-014 | `indicatif` steady_tick(Duration::from_millis(100)) or equivalent |
| No security mechanism weakened | ADR-001 | Progress reporting is presentation-only; no new I/O paths |
