# Story: Add MCP CLI Management (add/list/remove)

## Narrative
- **As a** factory operator or DarkClaw orchestration engine
- **I want to** manage MCP server connections to sandboxes via CLI commands (`mcp add`, `mcp list`, `mcp remove`)
- **So that** I can register, inspect, and tear down MCP servers without manually editing network policies, managing port forwards, or tracking bridge daemon PIDs

## Acceptance Criteria

### AC-001: `mcp add` registers server and starts bridge
`darkshell mcp add <sandbox> --name <server> --command <cmd> [--env <KEY>]` creates a registration file, starts the MCP bridge daemon (from DS-008), auto-allocates a port, starts a port forward into the sandbox, and auto-configures the sandbox network policy to allow the forwarded endpoint.
- **Test:** `test_mcp_add_registers_server_starts_bridge_and_forwards_port()`

### AC-002: `mcp add` records registration to disk
After `mcp add` completes, a registration YAML file exists at `~/.config/darkshell/mcp/<sandbox>-<server>.yaml` containing sandbox name, server name, transport, command, env keys, bridge PID, forwarded port, policy entry flag, and status.
- **Test:** `test_mcp_add_creates_registration_file_with_correct_fields()`

### AC-003: `mcp list` shows connected servers and status
`darkshell mcp list <sandbox>` displays all registered MCP servers for the sandbox, including server name, transport type, bridge PID, forwarded port, and connection status (running/stopped/error). Supports `--json` flag for machine-readable output.
- **Test:** `test_mcp_list_displays_all_registered_servers_with_status()`
- **Test:** `test_mcp_list_json_output_parseable_by_jq()`

### AC-004: `mcp remove` tears down all resources cleanly
`darkshell mcp remove <sandbox> --name <server>` stops the bridge daemon, removes the port forward, removes the auto-added network policy entry, and deletes the registration file.
- **Test:** `test_mcp_remove_stops_bridge_removes_forward_and_cleans_policy()`

### AC-005: `mcp remove` for non-existent server returns actionable error
`darkshell mcp remove <sandbox> --name <nonexistent>` returns an error message listing the available MCP servers for that sandbox.
- **Test:** `test_mcp_remove_nonexistent_server_shows_available_servers()`

### AC-006: Sandbox delete cleans up all MCP resources
When `darkshell sandbox delete <name>` is invoked, all MCP bridge daemons, PID files, port forwards, network policy entries, and registration files associated with that sandbox are cleaned up. Partial cleanup failure is logged but does not block sandbox deletion.
- **Test:** `test_sandbox_delete_cleans_up_all_mcp_resources()`
- **Test:** `test_sandbox_delete_partial_cleanup_failure_logged_not_blocking()`

### AC-007: `mcp add` with port conflict auto-increments
When the default port is already in use, `mcp add` selects the next available port starting from 9100, incrementing until a free port is found via `check_port_available()`.
- **Test:** `test_mcp_add_selects_next_available_port_on_conflict()`

### AC-008: `mcp list` for sandbox with no MCP servers returns empty result
`darkshell mcp list <sandbox>` on a sandbox with no registered MCP servers returns an empty table (human) or empty array (JSON) without error.
- **Test:** `test_mcp_list_empty_sandbox_returns_empty_without_error()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-017 | Bridge daemon running when sandbox is force-deleted | Bridge receives SIGTERM, cleans up within 5s. If bridge doesn't exit, SIGKILL after 10s. PID file removed regardless. |
| EC-019 | Port conflict when auto-allocating MCP bridge port | Bridge selects ports starting from 9100, increments until available via `check_port_available()`. Selected port recorded in registration file. |
| EC-CUSTOM-001 | `mcp add` called for server name that already exists on this sandbox | Error: "MCP server 'X' already registered on sandbox 'Y'. Use `mcp remove` first." |
| EC-CUSTOM-002 | Sandbox does not exist when `mcp add` is called | Fail fast: "Sandbox 'X' not found. Available: ..." |
| EC-CUSTOM-003 | Bridge daemon crashes between `mcp add` and `mcp list` | `mcp list` shows status as "error" with last-known PID. Does not attempt auto-restart (that is DS-008's responsibility). |
| EC-CUSTOM-004 | Network policy set fails after bridge is already started | Roll back: stop bridge, remove port forward, remove registration. Error includes policy set failure reason. |

## Architecture Compliance Rules

| Rule | Source | Enforcement |
|------|--------|-------------|
| Enhancements live in CLI crate and new crates, not sandbox runtime | ADR-001 | All new code in `openshell-cli/src/mcp.rs` and `darkshell-mcp/src/registry.rs` |
| MCP bridge runs on host, not in sandbox | ADR-002 | Bridge process spawned on host; port-forwarded into sandbox |
| No modification to existing upstream command semantics | ADR-008 | `mcp` is a new subcommand group; existing commands unchanged |
| MCP bridge traffic is outside sandbox proxy scope — compensating controls required | ADR-010 | This story implements CLI management; DS-010 adds tool-level policy; DS-013 adds logging |
| Actionable error messages | NFR-014 | Every error includes what failed, why, and how to fix |
| `--json` flag for structured output | NFR-015 | `mcp list` supports `--json` |
