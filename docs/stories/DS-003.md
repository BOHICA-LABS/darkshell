# Story: Support Multiple --upload on Sandbox Create

## Narrative
- **As a** DarkClaw orchestration engine (or operator)
- **I want to** specify multiple `--upload` flags when creating a sandbox, each mapping a local directory to a sandbox destination
- **So that** multi-directory workspace setup (engine, workspace, environment config) happens in a single create command instead of requiring N separate upload calls after creation

## Acceptance Criteria

### AC-001: Multiple --upload flags accepted on sandbox create
`darkshell sandbox create --name dev --from image:tag --upload src:/sandbox/src --upload config:/sandbox/config` accepts and processes both upload specifications.
- **Test:** `test_multiple_upload_flags_accepted()`

### AC-002: Each upload processes in declaration order
When multiple `--upload` flags are specified, uploads are processed sequentially in the order declared on the command line. The first `--upload` completes before the second begins.
- **Test:** `test_uploads_process_in_order()`

### AC-003: Single --upload remains backward compatible
`darkshell sandbox create --name dev --from image:tag --upload src:/sandbox` behaves identically to the upstream single-upload behavior. No regression.
- **Test:** `test_single_upload_backward_compatible()`

### AC-004: No --upload flag still works (create without upload)
`darkshell sandbox create --name dev --from image:tag` (no `--upload`) creates the sandbox without any upload, identical to upstream behavior.
- **Test:** `test_create_without_upload()`

### AC-005: Upload failure on Nth item reports which upload failed
If the second of three uploads fails, the error message includes which upload spec failed ("Upload failed for 'config:/sandbox/config': Permission denied on /sandbox/config"). Previous successful uploads are not rolled back.
- **Test:** `test_upload_failure_reports_which_spec()`

## Edge Cases
| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-003 | Two `--upload` specs target the same sandbox directory (e.g., `a:/sandbox` and `b:/sandbox`) | Second upload overwrites first (last-writer-wins). Log a warning: "Multiple uploads target '/sandbox'. Last upload ('b') will overwrite previous contents." |
| EC-M01 | Upload spec missing colon separator (e.g., `--upload src`) | Use upstream default destination (`/sandbox`). This matches upstream single-upload behavior. |
| EC-M02 | Upload spec with empty local path (e.g., `--upload :/sandbox/dest`) | Reject with error: "Invalid upload spec ':/sandbox/dest': local path is empty" |
| EC-M03 | Local directory does not exist for one of multiple uploads | Fail on that upload with actionable error. Previous uploads are not rolled back. Subsequent uploads are not attempted. |

|------|--------|-------------|
| No modification to existing upload semantics | ADR-008 | Single `--upload` produces identical behavior to upstream `Option<String>` |
