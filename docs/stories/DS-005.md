# Story: Add download --include/--exclude filtering

## Narrative
- **As a** factory operator
- **I want to** download only specific files from a sandbox using glob patterns
- **So that** I can retrieve just the artifacts I need (e.g., `.factory/` output) without downloading the entire multi-gigabyte workspace

## Acceptance Criteria

### AC-001: --include pattern filters downloaded files to only matching paths
When `darkshell sandbox download <name> <remote> --include '*.json'` is invoked, only files matching the glob pattern are included in the tar stream from the server side.
- **Test:** `test_download_include_filters_to_matching_files()`

### AC-002: --exclude pattern omits matching files from download
When `darkshell sandbox download <name> <remote> --exclude '*.log'` is invoked, files matching the exclude pattern are omitted from the tar stream.
- **Test:** `test_download_exclude_omits_matching_files()`

### AC-003: Multiple --include patterns are combined with OR semantics
When multiple `--include` flags are provided (e.g., `--include '*.json' --include '*.toml'`), files matching any of the patterns are included.
- **Test:** `test_download_multiple_include_patterns_union()`

### AC-004: Multiple --exclude patterns are combined with OR semantics
When multiple `--exclude` flags are provided, files matching any pattern are excluded.
- **Test:** `test_download_multiple_exclude_patterns_union()`

### AC-005: --include and --exclude can be combined; exclude takes precedence
When both flags are provided, files must match at least one include pattern AND not match any exclude pattern. Exclude wins on conflict.
- **Test:** `test_download_include_exclude_combined_exclude_wins()`

### AC-006: Glob patterns support *, **, and ? wildcards
Patterns like `src/**/*.rs`, `*.log`, and `config.?ml` match files using standard glob semantics.
- **Test:** `test_download_filter_glob_wildcards()`

### AC-007: Pattern matching no files produces warning and 0-byte download
When `--include` matches zero files, the download completes successfully with 0 bytes transferred and a warning message: `No files matched pattern '<pattern>'`.
- **Test:** `test_download_include_no_match_warns_and_succeeds()`

### AC-008: Server-side tar command applies filtering before transfer
Filtering is applied on the server side so that unmatched files are never transferred over the network. The server-side tar command uses `find` with pattern matching piped to tar, not client-side filtering.
- **Test:** `test_download_filter_applied_server_side()`

### AC-009: Client-side unpack is unchanged from upstream behavior
The client-side `tar::Archive::unpack()` logic remains identical to upstream. Only the server-side tar creation command is modified.
- **Test:** `test_download_filtered_unpack_matches_upstream()`

### AC-010: Download without --include/--exclude behaves identically to upstream
When no filter flags are provided, the download uses the original upstream tar command. No behavioral change to existing users.
- **Test:** `test_download_no_filter_matches_upstream_behavior()`

## Verification Properties

| ID | Property | Type | Tool |
|----|----------|------|------|
| VP-001 | For any set of include patterns, downloaded files are a subset of files matching at least one pattern | proptest | proptest |
| VP-002 | For any set of exclude patterns, no downloaded file matches any exclude pattern | proptest | proptest |
| VP-003 | With no filters, the set of downloaded files equals the full remote directory contents | proptest | proptest |

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-014 | `--include` pattern matches no files | Download completes with 0 bytes; warning: "No files matched pattern '<pattern>'" |
| EC-020 | Remote path does not exist | Error: "Remote path '/foo' not found in sandbox '<name>'" with exit code 1 |
| EC-021 | Include pattern contains invalid glob syntax | Error: "Invalid glob pattern '<pattern>': <parse error>. See glob(7) for syntax." |
| EC-022 | Remote directory is empty | Download completes with 0 bytes; no warning (empty is a valid state) |
| EC-023 | Pattern matches only symlinks | Symlinks included in tar (matching upstream behavior) |
| EC-024 | Very long pattern list (100+ patterns) | All patterns applied; server-side find command handles arbitrary pattern count |
