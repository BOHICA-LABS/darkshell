# Story: Add Inference Request/Response Logging Hook

## Narrative
- **As a** factory operator or security auditor
- **I want to** capture inference requests and responses (prompts, model provider, response content, token counts, latency) flowing through the sandbox proxy, with configurable redaction
- **So that** I can detect prompt injection, audit agent reasoning chains, measure inference costs, and identify data exfiltration through model API calls — all without modifying the proxy's routing or security behavior

## Acceptance Criteria

### AC-001: Narrow hook in proxy.rs captures inference events
A single observability hook is inserted at the inference routing point in `openshell-sandbox/src/proxy.rs`. The hook emits structured `InferenceEvent` records containing: prompt content, model provider, response content, token counts (prompt + completion), and request latency. The hook is clearly demarcated with `// BEGIN DARKSHELL HOOK` and `// END DARKSHELL HOOK` markers.
- **Test:** `test_proxy_hook_emits_inference_event()`

### AC-002: Hook is behind darkshell-inference-log feature flag
The proxy.rs hook is gated behind a `darkshell-inference-log` compile-time feature flag in `openshell-sandbox/Cargo.toml`. When the feature flag is disabled, the hook compiles to a no-op with zero runtime cost. The default build (without the flag) produces a binary identical in behavior to upstream.
- **Test:** `test_hook_compiles_to_noop_without_feature_flag()`

### AC-003: Inference events are delivered to darkshell-observe via channel
The proxy.rs hook sends `InferenceEvent` structs through a `tokio::sync::mpsc` channel to the `darkshell-observe` crate's `inference_log` module. The channel is bounded (capacity 1000) to prevent memory growth. If the channel is full, events are dropped and a counter is incremented (never blocks the proxy).
- **Test:** `test_inference_events_delivered_via_channel()`

### AC-004: Inference events appear in sandbox watch stream
When `darkshell sandbox watch <name> --type inference` is active, inference events appear in the JSON lines stream with event_type `inference`. Each event includes all fields from AC-001.
- **Test:** `test_inference_events_in_watch_stream()`

### AC-005: Configurable redaction strips PII from logged events
The `inference_log` module supports configurable redaction rules: `strip_pii` (regex-based PII removal), `hash_fields` (SHA-256 hash of specified fields), and `truncate` (limit prompt/response content to N tokens). Redaction is applied before events are emitted to the watch stream or any exporter. Default: no redaction (operator must opt in).
- **Test:** `test_redaction_strips_pii_from_events()`
- **Test:** `test_redaction_hashes_specified_fields()`
- **Test:** `test_redaction_truncates_to_token_limit()`

### AC-006: Redaction configuration is loaded from blueprint or CLI flag
Redaction rules are specified via `--inference-redaction <config.yaml>` on `sandbox watch` or via the `observe.inference_redaction` section in a blueprint. The configuration supports: `strip_pii: true/false`, `hash_fields: [prompt, response]`, `truncate_tokens: N`.
- **Test:** `test_redaction_config_from_cli_flag()`

### AC-007: Hook does not modify proxy request/response routing
The hook is strictly read-only. It observes the inference request and response after they have been routed but does not modify, delay, or block any traffic. Policy evaluation, TLS termination, SSRF protection, and all other proxy behaviors are unaffected.
- **Test:** `test_hook_does_not_modify_proxy_behavior()`

### AC-008: This is the only modification to openshell-sandbox
The `git diff` for the `openshell-sandbox` crate shows changes ONLY in `proxy.rs` (the hook insertion) and `Cargo.toml` (the feature flag). No other files in `openshell-sandbox` are modified. The hook is the minimal possible change — a single function call or channel send within the DARKSHELL HOOK markers.
- **Test:** `test_sandbox_crate_diff_is_minimal()`

## Edge Cases
| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-I01 | Inference response is streaming (chunked transfer encoding) | Hook captures the complete response by buffering chunks. If response exceeds 1MB, truncate and mark `truncated: true` in the event. |
| EC-I02 | Channel is full (observer not consuming fast enough) | Drop the event, increment `dropped_events` counter. Never block the proxy. Log a warning every 100 dropped events. |
| EC-I03 | Inference request fails (upstream returns 5xx) | Hook still emits an event with the error status code, empty response content, and `error: true` flag. |
| EC-I04 | Non-inference CONNECT request passes through proxy | Hook does not fire. Only requests to `inference.local` (the hardcoded inference bypass in proxy.rs) trigger the hook. |
| EC-I05 | Redaction config references a field that does not exist in the event | Silently skip the unknown field. Log a warning at config load time: "Redaction field 'foo' is not a valid InferenceEvent field. Valid fields: prompt, response, model, provider." |
| EC-I06 | Multiple concurrent inference requests | Each request gets its own InferenceEvent. Events may arrive out of order in the channel. Each event includes a unique request_id for correlation. |
| EC-I07 | Feature flag enabled but no observer is consuming the channel | Channel fills up, events are dropped (EC-I02 behavior). Proxy performance is unaffected. No resource leak. |

## Purity Classification

| Module | Classification | Justification |
|--------|---------------|---------------|
| `openshell-sandbox/src/proxy.rs` (hook site) | effectful-shell | Side effect: sends event to channel. Gated by feature flag. |
| `darkshell-observe/src/inference_log.rs` (event processing) | mixed | Receives events from channel (effectful), applies redaction (pure transformation), emits to watch stream (effectful) |
| `InferenceEvent` struct and serialization | pure-core | Data type definition and JSON serialization — no side effects |
| Redaction engine (PII stripping, hashing, truncation) | pure-core | Pure transformation of event content — no I/O, no state |

## Architecture Compliance Rules

| Rule | Source | Enforcement |
|------|--------|-------------|
| This is the ONLY modification to openshell-sandbox | ADR-001, ADR-011 | `git diff crates/openshell-sandbox/` shows changes ONLY in proxy.rs and Cargo.toml |
| Hook is behind compile-time feature flag | ADR-011 | `cargo build` without `--features darkshell-inference-log` produces upstream-identical sandbox binary |
| Hook is read-only — no modification to request/response routing | ADR-011 | Hook code contains no mutation of `req`, `resp`, or any routing/policy state |
| Hook is clearly demarcated with BEGIN/END markers | ADR-011 | Markers present in proxy.rs for upstream merge management |
| Redaction is applied before any event emission | SOUL.md Rule 4 (silent failures) | Redaction pipeline runs synchronously before channel send or watch stream emission |
| Channel never blocks the proxy | NFR-005, ADR-011 | Use `try_send()` not `send().await`; drop on full channel |
| Security mechanisms unaffected | NFR-006, SOUL.md Rule 11 | Hook does not touch Landlock, seccomp, netns, OPA, SSRF, or TLS code paths |
