# Story: Add upload --dry-run preview

## Narrative
- **As a** factory operator
- **I want to** preview what files would be uploaded (added, modified, deleted) before actually transferring them
- **So that** I can verify the upload will do what I expect and avoid accidentally overwriting sandbox-side changes

## Acceptance Criteria

### AC-001: --dry-run shows files that would be added to the sandbox
When `darkshell sandbox upload <name> <local> --dry-run` is invoked and the sandbox does not have files that exist locally, those files are listed as "added" in the output.
- **Test:** `test_dry_run_shows_added_files()`

### AC-002: --dry-run shows files that would be modified in the sandbox
When local files differ from their sandbox counterparts (different hash), those files are listed as "modified" in the output.
- **Test:** `test_dry_run_shows_modified_files()`

### AC-003: --dry-run shows files that exist in sandbox but not locally as deletable
When the sandbox contains files that are not present in the local directory (and rsync `--delete` would remove them), those files are listed as "would be deleted" in the output.
- **Test:** `test_dry_run_shows_deleted_files()`

### AC-004: --dry-run performs no actual file transfer
When `--dry-run` is specified, zero bytes are transferred to the sandbox. The sandbox filesystem is unchanged after the command completes.
- **Test:** `test_dry_run_transfers_zero_bytes()`

### AC-005: --dry-run works with tar upload mode
When `--dry-run` is used without `--rsync`, the preview uses exec to get sandbox file hashes for comparison against local hashes. The file listing is the same format as rsync mode.
- **Test:** `test_dry_run_works_with_tar_mode()`

### AC-006: --dry-run works with rsync upload mode
When `--dry-run` is used with `--rsync`, the preview delegates to `rsync --dry-run` for accurate delta computation.
- **Test:** `test_dry_run_works_with_rsync_mode()`

### AC-007: --dry-run --json outputs machine-readable JSON
When both `--dry-run` and `--json` flags are provided, the output is a JSON object with `added`, `modified`, and `deleted` arrays of file paths.
- **Test:** `test_dry_run_json_output_is_valid()`

### AC-008: --dry-run with empty local directory shows all sandbox files as deletable
When the local directory is empty (or all files are gitignored), all sandbox files in the destination are listed as "would be deleted."
- **Test:** `test_dry_run_empty_local_shows_all_deleted()`

### AC-009: --dry-run with empty sandbox destination shows all local files as added
When the sandbox destination does not exist or is empty, all local files are listed as "added."
- **Test:** `test_dry_run_empty_sandbox_shows_all_added()`

### AC-010: --dry-run summary shows counts
The output ends with a summary line: `N file(s) to add, M file(s) to modify, K file(s) to delete`.
- **Test:** `test_dry_run_summary_counts()`

## Verification Properties

| ID | Property | Type | Tool |
|----|----------|------|------|
| VP-001 | For any local and remote file sets, every file appears in exactly one category (added, modified, deleted, or unchanged) | proptest | proptest |
| VP-002 | Dry-run never invokes tar or rsync in transfer mode (only exec for hashing) | proof | code review — assert no transfer subprocess spawned |

| Component | Interaction Type |

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-030 | Sandbox destination does not exist | All local files shown as "added"; no error (directory would be created on actual upload) |
| EC-031 | Local directory contains only .gitignore'd files and upload uses git filtering | Dry-run shows 0 files to add; summary: "0 file(s) to add, 0 file(s) to modify, 0 file(s) to delete" |
| EC-032 | exec to get sandbox hashes fails (sandbox not running) | Error: "Cannot preview upload: sandbox '<name>' is not running. Start the sandbox first." |
| EC-033 | Very large directory (100K+ files) | Dry-run completes within 30s; hash comparison is done server-side via exec to avoid transferring individual hashes |
| EC-034 | Symlinks in local directory | Follow symlinks for hashing (matching rsync -L behavior per ADR-003) |
| EC-035 | File permissions differ but content is identical | File not listed as modified (content-only comparison, not metadata) |

## Purity Classification

| Module | Classification | Justification |
|--------|---------------|---------------|
| `ssh.rs` (diff computation) | pure-core | Compares two sets of (path, hash) tuples — no I/O |
| `ssh.rs` (local hash collection) | effectful-shell | Reads filesystem to compute file hashes |
| `ssh.rs` (remote hash collection via exec) | effectful-shell | Executes SSH command to get sandbox hashes |
| `ssh.rs` (dry-run output formatting) | pure-core | Formats diff results for display — no I/O |
