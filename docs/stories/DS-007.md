# Story: Add sandbox exec with SSH ControlMaster

## Narrative
- **As a** DarkClaw orchestration engine (or factory operator)
- **I want to** execute commands inside a sandbox and receive stdout, stderr, and exit code without an interactive SSH session
- **So that** I can run hundreds of quick commands per factory run (git status, cargo build, agent queries) with minimal overhead (<100ms steady-state)

## Acceptance Criteria

### AC-001: exec runs command and returns stdout on stdout
When `darkshell sandbox exec <name> -- echo hello` is invoked, `hello\n` is printed to the CLI's stdout.
- **Test:** `test_exec_returns_stdout()`

### AC-002: exec returns stderr on stderr
When the command produces stderr output, it is printed to the CLI's stderr stream, separate from stdout.
- **Test:** `test_exec_returns_stderr_on_stderr()`

### AC-003: exec returns the command's exit code as the CLI exit code
When the remote command exits with code 42, `darkshell sandbox exec` also exits with code 42.
- **Test:** `test_exec_propagates_exit_code()`

### AC-004: Default timeout of 300 seconds kills the command
When a command runs longer than 300 seconds (the default), the SSH process is killed and exit code 124 (timeout convention) is returned with a warning on stderr.
- **Test:** `test_exec_default_timeout_kills_after_300s()`

### AC-005: --timeout <secs> overrides default timeout
When `--timeout 10` is specified, the command is killed after 10 seconds instead of the default 300.
- **Test:** `test_exec_custom_timeout()`

### AC-006: --timeout 0 disables timeout entirely
When `--timeout 0` is specified, the command runs indefinitely until it completes or is externally interrupted.
- **Test:** `test_exec_timeout_zero_disables()`

### AC-007: --json wraps output in structured JSON
When `--json` is specified, the output is a JSON object: `{"stdout": "...", "stderr": "...", "exit_code": N, "duration_ms": N}`.
- **Test:** `test_exec_json_output_format()`

### AC-008: SSH ControlMaster reuses connections for subsequent exec calls
The first exec to a sandbox establishes an SSH ControlMaster connection (~200ms). Subsequent exec calls to the same sandbox reuse the multiplexed connection with < 20ms overhead.
- **Test:** `test_exec_controlmaster_reuse_reduces_latency()`

### AC-009: ControlSocket stored at standard path
The SSH ControlSocket is stored at `~/.config/darkshell/ssh/ctrl-%r@%h:%p`. The directory is created if it does not exist.
- **Test:** `test_exec_controlsocket_path()`

### AC-010: ControlPersist keeps connection alive for 600 seconds
The SSH connection persists for 600 seconds after the last exec command. After 600 seconds of inactivity, the master connection is automatically closed.
- **Test:** `test_exec_controlpersist_timeout()`

### AC-011: exec uses same ProxyCommand transport as upstream SSH
The exec command uses the identical SSH ProxyCommand tunnel through the gateway as upstream `sandbox connect`. No new network paths are introduced.
- **Test:** `test_exec_uses_proxycommand_transport()`

### AC-012: exec to non-existent sandbox produces actionable error
When the sandbox name doesn't exist, the error message includes: what failed, the invalid sandbox name, and how to list available sandboxes.
- **Test:** `test_exec_nonexistent_sandbox_error()`

### AC-013: Timeout event is logged as warning
When a timeout occurs, a structured warning is emitted via tracing: `sandbox=<name>, command=<cmd>, timeout_secs=<N>`.
- **Test:** `test_exec_timeout_logs_warning()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-005 | Command produces unbounded stdout (e.g., `cat /dev/urandom`) | Stream output without buffering in CLI; respect SSH channel limits. Timeout kills the process. |
| EC-006 | Command hangs indefinitely | Default 300s timeout kills SSH process, returns exit code 124. `--timeout 0` disables. Timeout logged as warning. |
| EC-040 | ControlSocket file already exists from a stale session | SSH detects stale socket automatically and re-establishes ControlMaster |
| EC-041 | Sandbox deleted while ControlMaster connection is open | SSH connection drops; next exec attempt gets connection error with actionable message: "Sandbox '<name>' is no longer available" |
| EC-042 | Command contains special shell characters (pipes, redirects) | Entire command after `--` is passed as a single string to `ssh -T`, preserving shell interpretation on the remote side |
| EC-043 | Multiple concurrent exec calls to the same sandbox | SSH ControlMaster multiplexes all calls over the same connection. Each call gets independent stdout/stderr/exit code. |
| EC-044 | SSH config directory does not exist | Created automatically with mode 0700 before first exec |
| EC-045 | Command produces binary output (non-UTF8) | Raw bytes passed through without encoding. --json mode base64-encodes stdout/stderr. |

## Architecture Compliance Rules

| Rule | Source | Enforcement |
|------|--------|-------------|
| Same ProxyCommand transport as upstream | ADR-003, ADR-008 | Exec uses identical SSH tunnel config as `sandbox connect` |
| SSH ControlMaster for performance | ADR-009 | ControlMaster=auto, ControlPersist=600, ControlSocket at standard path |
| No modification to sandbox runtime | ADR-001 | exec is purely CLI-side; SSH -T is non-interactive remote execution |
| Actionable error messages | NFR-014 | Errors include sandbox name, failure reason, remediation |
| Machine-readable JSON output | NFR-015 | --json produces valid JSON with stdout, stderr, exit_code, duration_ms |
| Exec overhead < 100ms steady-state | NFR-002 | ControlMaster reuse brings subsequent calls to < 20ms |
| SSH connection reuse < 20ms | NFR-018 | Measured via benchmark of 10 sequential exec calls |
