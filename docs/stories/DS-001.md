# Story: Fork OpenShell, Rename Binary, Verify Build

## Narrative
- **As a** DarkShell developer
- **I want to** fork NVIDIA OpenShell, merge upstream into the DarkShell repo, rename the binary from `openshell` to `darkshell`, and verify the full build pipeline passes
- **So that** the project has a clean foundation with upstream compatibility, a distinct binary name, and a green CI baseline before any enhancements begin

## Acceptance Criteria

### AC-001: Upstream remote is configured and upstream code is merged
The `upstream` git remote points to `https://github.com/NVIDIA/OpenShell.git`, and `upstream/main` is merged into the `develop` branch with full commit history preserved.
- **Test:** `test_upstream_remote_configured()`

### AC-002: Binary is renamed from openshell to darkshell
The CLI binary produced by `cargo build` is named `darkshell` (controlled by `[[bin]]` in `crates/openshell-cli/Cargo.toml`). The `--help` output references `darkshell`, not `openshell`.
- **Test:** `test_binary_named_darkshell()`

### AC-003: Cargo.toml metadata updated for DarkShell
The root `Cargo.toml` and `crates/openshell-cli/Cargo.toml` have updated `description`, `repository` (pointing to `BOHICA-LABS/darkshell`), and binary name. Internal crate names (`openshell-cli`, `openshell-core`, etc.) remain unchanged to preserve upstream merge compatibility.
- **Test:** `test_cargo_metadata_updated()`

### AC-004: All upstream tests pass under the new binary name
`cargo test --workspace` passes with zero failures. No upstream tests are skipped, deleted, or modified.
- **Test:** `test_upstream_test_suite_passes()`

### AC-005: Clippy is clean with no warnings
`cargo clippy --workspace --all-targets --all-features -- -D warnings` exits with code 0.
- **Test:** `test_clippy_clean()`

### AC-006: cargo build succeeds for all workspace crates
`cargo build --workspace` completes successfully, producing the `darkshell` binary in the target directory.
- **Test:** `test_cargo_build_succeeds()`

### AC-007: Upstream merge strategy is documented
A `NOTICE` file exists at the repo root with Apache 2.0 fork attribution, and the upstream remote relationship is documented in `CLAUDE.md`.
- **Test:** `test_notice_file_exists()`
